01

데이터베이스 개념

데이터베이스 정의, DBMS 기능, 스키마, SQL 언어 분류가 나옵니다. 1급에서만 보는 과목이라 생소하지만 범위가 일정해 기출 반복 효과가 큽니다.

2027 출제기준2027–2029 기준에서도 프로그램은 MS Office 2021(Access 2021) 그대로입니다. 이 교재는 2026년 6월 발표된 출제기준의 세세항목과 대조해 정리했습니다.

데이터베이스의 정의와 특징

중요도 ★★★
정의뜻
통합 데이터중복을 최소화해 통합한 데이터
저장 데이터컴퓨터가 접근할 수 있는 저장 매체에 저장된 데이터
운영 데이터조직의 업무에 꼭 필요한 데이터
공용 데이터여러 사용자와 응용 프로그램이 함께 쓰는 데이터
  • 실시간 접근: 요청에 즉시 응답합니다.
  • 계속적인 변화: 삽입, 삭제, 갱신으로 항상 최신 상태를 유지합니다.
  • 동시 공유: 여러 사용자가 동시에 같은 데이터를 씁니다.
  • 내용에 의한 참조: 주소가 아니라 데이터의 내용(값)으로 찾습니다.

DBMS

중요도 ★★★

DBMS(데이터베이스 관리 시스템)는 기존 파일 시스템의 데이터 중복과 데이터 종속 문제를 해결하기 위한 소프트웨어입니다.

필수 기능뜻
정의 기능데이터의 형태, 구조, 제약 조건을 정함
조작 기능데이터 검색, 삽입, 삭제, 갱신
제어 기능무결성 유지, 보안, 권한 검사, 병행 수행 제어
장점단점
중복 최소화, 데이터 공유, 일관성·무결성·보안 유지, 표준화, 데이터 독립성운영비 증가, 전문 인력 필요, 백업·회복이 복잡, 시스템이 복잡

스키마와 데이터 독립성

중요도 ★★★
스키마뜻
외부 스키마사용자나 응용 프로그램이 보는 개인적 관점의 구조. 서브 스키마라고도 함. 여러 개 존재
개념 스키마조직 전체의 관점에서 본 데이터베이스 전체의 논리적 구조. 하나만 존재. 무결성 규칙과 접근 권한 포함
내부 스키마저장 장치 관점의 물리적 저장 구조 (레코드 형식, 인덱스, 저장 순서)
  • 논리적 독립성: 개념 스키마가 바뀌어도 외부 스키마(응용 프로그램)에 영향이 없습니다.
  • 물리적 독립성: 내부 스키마(저장 구조)가 바뀌어도 개념 스키마에 영향이 없습니다.

데이터베이스 언어와 사용자

중요도 ★★★
언어명령용도
DDL (정의어)CREATE, ALTER, DROP테이블 등 구조를 만들고, 바꾸고, 삭제
DML (조작어)SELECT, INSERT, UPDATE, DELETE데이터 검색, 삽입, 수정, 삭제
DCL (제어어)GRANT, REVOKE, COMMIT, ROLLBACK권한 부여·회수, 작업 확정·취소
함정DROP은 구조(테이블 자체)를 지우는 DDL, DELETE는 레코드를 지우는 DML입니다. ALTER(구조 변경)와 UPDATE(값 수정)도 같은 관계입니다.
  • 데이터베이스 관리자(DBA): 스키마 정의, 저장 구조와 접근 방법 결정, 보안·권한 관리, 백업·회복 절차 수립, 성능 감시를 맡습니다.
  • 응용 프로그래머: 호스트 언어에 DML을 넣어 프로그램을 만듭니다. 일반 사용자: 질의어로 데이터를 조회합니다.
  • 트랜잭션: 하나의 논리적 작업 단위. 원자성(전부 실행 또는 전부 취소), 일관성, 독립성(격리성), 지속성(영속성)을 가집니다.

데이터베이스 구성 요소, 종류, 구축 절차

중요도 ★★☆
구성 요소뜻
개체 (Entity)저장할 가치가 있는 대상. 학생, 상품처럼 테이블이 되는 것
속성 (Attribute)개체를 설명하는 가장 작은 논리적 단위. 이름, 가격
관계 (Relationship)개체와 개체 사이의 연관성. 학생이 강좌를 '수강'

데이터베이스 시스템은 데이터베이스, DBMS, 데이터베이스 언어, 사용자(DBA 등), 하드웨어로 구성됩니다.

종류특징
관계형2차원 표(테이블)로 표현. Access, Oracle, MySQL, SQL Server
계층형트리 구조(부모-자식). 일대다 관계만 표현
네트워크형그래프 구조. 다대다 관계 표현 가능하지만 구조가 복잡
객체 지향형데이터와 동작을 객체로 묶어 저장. 멀티미디어 데이터에 적합
NoSQL정해진 표 구조 없이 대용량·비정형 데이터 처리 (빅데이터, 웹 서비스)

구축 절차: 요구 조건 분석 → 개념적 설계 → 논리적 설계 → 물리적 설계 → 구현 → 운영·유지 보수. 설계 단계의 자세한 내용은 2단원에 있습니다.

02

데이터 모델, 키, 정규화

관계형 데이터베이스 용어, 키의 종류, 무결성, 정규화 단계가 매회 나옵니다.

데이터 모델과 설계 단계

중요도 ★★☆

설계 순서: 요구 조건 분석 → 개념적 설계 → 논리적 설계 → 물리적 설계 → 구현

  • 개념적 설계: 현실 세계를 E-R 다이어그램 같은 개념적 모델로 표현합니다. DBMS와 무관합니다.
  • 논리적 설계: 특정 DBMS(관계형 등)에 맞는 스키마로 바꾸고 정규화합니다.
  • 물리적 설계: 저장 구조, 인덱스, 접근 경로를 정합니다.
  • 논리적 데이터 모델: 관계형(표 형태, 가장 널리 사용) · 계층형(트리 구조) · 네트워크형(그래프 구조).
E-R 다이어그램 기호뜻
사각형개체 (Entity)
마름모관계 (Relationship)
타원속성 (Attribute)
밑줄 친 타원기본키 속성

선개체와 속성, 개체와 관계를 연결

키와 무결성

중요도 ★★★
키뜻
슈퍼키튜플을 구별할 수 있는 속성 집합. 유일성만 만족
후보키유일성과 최소성을 모두 만족하는 키
기본키후보키 중 선택한 대표 키. NULL 불가, 중복 불가
대체키후보키 중 기본키로 선택되지 않은 나머지
외래키다른 테이블의 기본키를 참조하는 속성. 테이블 간 관계를 만듦
무결성규칙
개체 무결성기본키는 NULL이나 중복 값을 가질 수 없음
참조 무결성외래키 값은 참조하는 테이블의 기본키 값이거나 NULL이어야 함
도메인 무결성속성 값은 정의된 도메인 범위 안의 값이어야 함

정규화

중요도 ★★★

정규화는 테이블을 나누어 중복을 줄이고 이상 현상을 없애는 과정입니다. 정보 손실 없이 분해(무손실 분해)해야 합니다.

  • 이상 현상: 삽입 이상(원치 않는 값까지 넣어야 함), 삭제 이상(필요한 정보까지 지워짐), 갱신 이상(일부만 바뀌어 불일치).
단계조건
1NF모든 속성 값이 원자값
2NF1NF + 부분 함수 종속 제거 (기본키 전체에 완전 함수 종속)
3NF2NF + 이행적 함수 종속 제거 (A→B, B→C일 때 A→C 제거)
BCNF3NF + 모든 결정자가 후보키
4NFBCNF + 다치 종속 제거
5NF4NF + 조인 종속 제거
외우는 법"도부이결다조" — 도메인 원자값 · 부분 종속 · 이행 종속 · 결정자 · 다치 종속 · 조인 종속

정규화를 많이 할수록 테이블이 늘어나 조인이 많아지므로 검색 속도가 느려질 수 있습니다.

데이터 형식, 필드 속성, 입력 마스크, 기본키와 인덱스가 나옵니다. 입력 마스크 기호는 실기에도 나오니 확실히 외우세요.

기본키와 인덱스

중요도 ★★★
  • 기본키는 필드 여러 개를 묶어 지정할 수 있습니다(복합키). 행 선택기에서 Ctrl을 누른 채 여러 필드를 고르고 지정합니다.
  • 기본키를 지정하면 자동으로 인덱스(중복 불가능)가 설정됩니다.
  • 기본키 없이도 테이블을 저장할 수 있습니다. 저장할 때 기본키를 만들지 묻고, '예'를 누르면 일련번호 필드가 추가됩니다.
  • 이미 중복 값이나 빈 값이 있는 필드는 기본키로 지정할 수 없습니다.
  • 인덱스는 검색과 정렬을 빠르게 하지만, 데이터를 추가·수정할 때는 인덱스도 갱신해야 해서 느려집니다. 자주 검색·정렬하는 필드에만 설정합니다.

데이터베이스 파일 관리와 인쇄

중요도 ★★☆
  • 새 데이터베이스: 빈 데이터베이스나 서식 파일(템플릿)로 만듭니다. 만들 때 파일 이름과 위치를 먼저 정합니다.
  • 데이터베이스 압축 및 복구: 삭제한 개체·레코드가 차지하던 공간을 정리해 파일 크기를 줄이고 손상된 파일을 복구합니다. 닫을 때 자동으로 압축하도록 설정할 수 있습니다.
  • 암호 설정: 데이터베이스를 단독 사용 모드로 열어야 암호를 지정·해제할 수 있습니다.
  • 백업: 파일 › 다른 이름으로 저장 › 데이터베이스 백업.
  • 데이터베이스 분할: 테이블(백 엔드)과 쿼리·폼·보고서(프런트 엔드)를 나눠 여러 사용자가 함께 씁니다.
  • ACCDE 파일 만들기: VBA 코드를 컴파일해 숨기고 폼·보고서·모듈의 디자인 변경을 막습니다.
  • 테이블·쿼리의 데이터시트, 폼, 보고서를 모두 인쇄할 수 있습니다. 출력용으로는 보고서를 씁니다.
  • 인쇄 미리 보기에서 용지 크기, 방향, 여백, 확대/축소를 조정하고 PDF·엑셀 등으로 바로 내보낼 수 있습니다.
  • 페이지 설정: 인쇄 옵션 탭(여백, 데이터만 인쇄), 페이지 탭(용지 방향, 크기, 프린터), 열 탭(열 개수, 행·열 간격, 열 레이아웃 '행 우선/열 우선').

04

관계, 조인, 외부 데이터

참조 무결성 옵션과 조인 종류의 차이가 자주 나옵니다.

관계 설정과 참조 무결성

중요도 ★★★
  • 관계 종류: 일대일(1:1), 일대다(1:N), 다대다(M:N). 다대다는 Access에서 직접 만들 수 없고, 가운데에 연결 테이블을 두어 일대다 관계 두 개로 만듭니다.
  • 관계를 맺는 두 필드는 데이터 형식이 같아야 합니다. 예외로 일련번호 필드는 숫자(정수 Long) 필드와 연결할 수 있습니다.
  • '일' 쪽 필드는 기본키이거나 고유 인덱스여야 참조 무결성을 설정할 수 있습니다.
참조 무결성 옵션효과
항상 참조 무결성 유지'다' 쪽에 '일' 쪽에 없는 값을 입력할 수 없음. 관련 레코드가 있는 '일' 쪽 레코드는 삭제·수정 불가
관련 필드 모두 업데이트'일' 쪽 기본키 값을 바꾸면 '다' 쪽 외래키 값도 자동으로 바뀜
관련 레코드 모두 삭제'일' 쪽 레코드를 지우면 '다' 쪽 관련 레코드도 함께 삭제

조인

중요도 ★★★
조인결과
내부 조인 (INNER JOIN)두 테이블에서 조인 필드 값이 일치하는 레코드만
왼쪽 외부 조인 (LEFT JOIN)왼쪽 테이블의 모든 레코드 + 오른쪽에서 일치하는 레코드
오른쪽 외부 조인 (RIGHT JOIN)오른쪽 테이블의 모든 레코드 + 왼쪽에서 일치하는 레코드

예: SELECT 학생.이름, 성적.점수 FROM 학생 INNER JOIN 성적 ON 학생.학번 = 성적.학번;

외부 데이터 가져오기·연결·내보내기

중요도 ★★☆
  • 가져오기: 엑셀, 텍스트, 다른 Access 파일의 데이터를 복사해 새 테이블로 만듭니다. 원본과 연결되지 않습니다.
  • 연결: 원본 데이터는 그대로 두고 연결만 합니다. 원본이 바뀌면 반영됩니다. 연결 테이블을 삭제해도 원본은 삭제되지 않습니다.
  • 엑셀에서 가져올 때 시트 단위나 이름 정의된 범위 단위로 가져오고, 첫 행을 필드 이름으로 쓸 수 있습니다. 가져오지 않을 필드를 고를 수도 있습니다.
  • 내보내기: 테이블, 쿼리, 폼, 보고서를 엑셀, 텍스트, PDF, 다른 Access 파일 등으로 저장합니다. 테이블을 다른 Access 파일로 내보낼 때는 구조만 또는 구조와 데이터를 고를 수 있습니다.

쿼리와 SQL

3과목에서 가장 많이 나오는 단원입니다. SQL 문의 결과를 묻는 문제가 매회 여러 문항 나옵니다.

쿼리의 종류

중요도 ★★★
쿼리특징
선택 쿼리조건에 맞는 레코드 검색. 가장 기본
매개 변수 쿼리실행할 때 값을 입력받음. 조건에 [검색할 이름을 입력하세요]처럼 대괄호 사용
요약 쿼리그룹별 합계·평균·개수 (요약 행 사용)
크로스탭 쿼리엑셀 피벗처럼 행·열로 요약. 행 머리글은 최대 3개, 열 머리글은 1개, 값은 1개
테이블 만들기쿼리 결과로 새 테이블 생성
추가 쿼리다른 테이블에 레코드 추가
업데이트 쿼리조건에 맞는 레코드의 값을 한꺼번에 수정
삭제 쿼리조건에 맞는 레코드 삭제
중복 데이터 검색필드 값이 같은 레코드 찾기 (마법사)
불일치 검색한 테이블에는 있고 다른 테이블에는 관련 레코드가 없는 것 찾기 (마법사)

테이블 만들기·추가·업데이트·삭제 쿼리를 실행 쿼리라고 하며, 실행하면 데이터가 실제로 바뀝니다. 실행 쿼리는 되돌릴 수 없습니다.

쿼리 디자인의 조건 행: 같은 행에 쓴 조건은 AND, 다른 행('또는')에 쓴 조건은 OR입니다.

SELECT 문

중요도 ★★★
SELECT [DISTINCT] 필드1, 필드2, 집계함수(필드) AS 별칭
FROM 테이블
WHERE 조건
GROUP BY 필드
HAVING 그룹 조건
ORDER BY 필드 [ASC | DESC];
  • DISTINCT: 중복된 결과를 하나만 표시합니다. SELECT *는 모든 필드입니다.
  • WHERE는 그룹으로 묶기 전의 레코드 조건, HAVING은 GROUP BY로 묶은 그룹의 조건입니다. 집계 함수 조건은 HAVING에 씁니다.
  • ORDER BY는 생략하면 오름차순(ASC)입니다. 여러 필드로 정렬하면 앞의 필드가 먼저 기준이 됩니다.
  • 집계 함수: COUNT, SUM, AVG, MAX, MIN. COUNT(*)는 전체 레코드 수, COUNT(필드)는 그 필드가 NULL이 아닌 레코드 수입니다.
조건 연산자예
BETWEEN a AND b점수 BETWEEN 70 AND 80 (70 이상 80 이하)
IN (…)부서 IN ("영업","기획")
LIKE이름 LIKE "김*" (김으로 시작) · "*수" (수로 끝남) · "*영*" (영 포함)
IS NULL / IS NOT NULL전화 IS NULL (값이 없음)
AND / OR / NOTNOT 부서 = "영업"

Access 와일드카드: *(여러 글자), ?(한 글자), #(숫자 한 자리), [ ](괄호 안의 문자 중 하나), [! ](괄호 안 문자 제외). 날짜는 #2026-10-02#처럼 #로 감쌉니다.

계산 쿼리와 별칭(alias)

중요도 ★★★
  • 쿼리 디자인의 필드 행에 금액: [단가]*[수량]처럼 입력하면 콜론 앞이 새 필드 이름이 되는 계산 필드가 생깁니다.
  • 같은 내용을 SQL로 쓰면 SELECT 상품명, 단가*수량 AS 금액 FROM 주문;입니다. AS 뒤가 별칭입니다.
  • 테이블에도 별칭을 붙일 수 있습니다: SELECT s.이름 FROM 사원 AS s;
  • 문자 연결은 &를 씁니다: 성명: [성] & [이름]
  • 계산 필드에 이름을 붙이지 않으면 Access가 'Expr1' 같은 이름을 자동으로 붙입니다.
  • 요약 쿼리에서 집계 결과에 별칭을 붙이면 결과 표의 열 이름이 바뀝니다: SELECT 부서, AVG(급여) AS 평균급여 FROM 사원 GROUP BY 부서;
06

폼

컨트롤 종류, 폼·컨트롤 속성, 하위 폼이 나옵니다.

폼의 기본

중요도 ★★★
  • 폼은 테이블·쿼리의 데이터를 입력·수정·조회하는 화면입니다. 폼에서 입력한 데이터는 원본 테이블에 저장됩니다.
  • 레코드 원본: 폼이 사용할 테이블, 쿼리, SQL 문.
  • 보기: 폼 보기(데이터 입력) · 데이터시트 보기 · 레이아웃 보기(데이터를 보면서 크기·위치 조정) · 디자인 보기(구조 편집, 데이터는 보이지 않음).
  • 폼 형식: 단일 폼(한 번에 레코드 하나), 연속 폼(여러 레코드), 데이터시트, 분할 폼(위는 폼, 아래는 데이터시트가 동기화), 여러 항목.
  • 구역: 폼 머리글, 페이지 머리글, 본문, 페이지 바닥글, 폼 바닥글. 페이지 머리글·바닥글은 인쇄할 때만 나타납니다.

컨트롤

중요도 ★★★
구분뜻
바운드 컨트롤테이블·쿼리의 필드와 연결된 컨트롤
언바운드 컨트롤필드와 연결되지 않은 컨트롤 (레이블, 선, 그림)
계산 컨트롤컨트롤 원본이 = 로 시작하는 식. 예: =[단가]*[수량]
컨트롤특징
텍스트 상자값 입력·표시. 계산 결과 표시
레이블제목·설명 문자 표시 (언바운드)
콤보 상자목록에서 고르거나 직접 입력도 가능. 공간을 적게 차지
목록 상자목록에서 고르기만 가능. 목록이 항상 펼쳐져 있음
확인란 / 옵션 단추 / 토글 단추Yes/No 값 표시
옵션 그룹여러 옵션 중 하나만 선택. 그룹 값은 숫자
명령 단추클릭으로 매크로나 이벤트 프로시저 실행
하위 폼폼 안에 다른 폼 넣기
탭 컨트롤여러 페이지를 탭으로 나눠 표시

계산 컨트롤 예: =Count(*)(레코드 수), =Sum([금액]), =Avg([점수]), =DSum("금액","주문","고객='김민지'")

폼과 컨트롤 속성

중요도 ★★★
폼 속성뜻
기본 보기단일 폼, 연속 폼, 데이터시트, 분할 표시 폼

하위 폼

중요도 ★★☆
  • 일대다 관계의 데이터를 함께 보여줍니다. 기본 폼은 '일' 쪽, 하위 폼은 '다' 쪽입니다.
  • 기본 필드 연결(기본 폼의 필드)과 하위 필드 연결(하위 폼의 필드)로 두 폼을 연결합니다. 두 필드의 데이터 형식이 같아야 합니다.
  • 기본 폼은 단일 폼으로만 표시하고, 하위 폼은 연속 폼이나 데이터시트로 표시할 수 있습니다.
  • 하위 폼은 여러 단계로 중첩할 수 있습니다(최대 7수준).

폼의 조건부 서식, 차트, 가져오기·내보내기

중요도 ★★☆
  • 조건부 서식: 텍스트 상자, 콤보 상자 같은 컨트롤에 적용합니다. 기준은 필드 값, 식(예: [재고]<10), 포커스가 있는 필드입니다. 데이터 막대도 표시할 수 있습니다.
  • 차트: 폼이나 보고서에 차트 컨트롤을 넣고, 데이터 원본(테이블·쿼리)과 축·값 필드를 지정합니다.
  • 폼 가져오기: [외부 데이터 › 새 데이터 원본 › 데이터베이스에서 › Access]로 다른 데이터베이스의 폼을 가져옵니다.
  • 폼 내보내기: 폼을 PDF, 엑셀, 텍스트 등으로 내보내거나 다른 Access 데이터베이스로 복사합니다. 엑셀로 내보내면 폼의 데이터가 내보내집니다.

중요도 ★★★
구역인쇄 위치

  • 보고서에서는 데이터를 입력·수정할 수 없습니다.

그룹화, 정렬, 계산

중요도 ★★★
  • '그룹화 및 정렬'에서 그룹·정렬 기준을 최대 10개 수준까지 지정합니다.
  • 그룹 속성: 머리글·바닥글 표시, 그룹 간격(첫 글자, 월, 분기 등), 같은 페이지에 표시(그룹 전체를 한 페이지에).
  • 누적 합계 속성: '그룹'은 그룹 안에서만 누적, '모두'는 보고서 전체 누적. 컨트롤 원본을 =1로 하고 누적 합계를 쓰면 일련번호가 됩니다.
  • 중복 내용 숨기기: 바로 위 레코드와 값이 같으면 표시하지 않습니다.
  • 그룹 바닥글에 =Sum([금액])을 넣으면 그룹별 합계, 보고서 바닥글에 넣으면 전체 합계입니다.

보고서 만들기 도구

중요도 ★★☆
  • 보고서: 선택한 테이블·쿼리로 바로 만듭니다.
  • 보고서 마법사: 필드, 그룹, 정렬, 요약 옵션, 모양을 단계별로 선택합니다.
  • 레이블: 우편물 주소 라벨 같은 표준 크기 라벨을 만듭니다.
  • 업무 문서 양식 마법사: 거래명세서, 세금계산서 같은 양식을 만듭니다.
  • 보고서의 레코드 원본도 테이블, 쿼리, SQL 문을 쓸 수 있습니다.

우편 엽서 보고서와 보고서 서식

중요도 ★★☆
  • 우편 엽서 마법사: 엽서 크기와 종류를 고르고 받는 사람·보내는 사람 정보를 배치해 우편 엽서 보고서를 만듭니다.
  • 레이블 마법사: 레이블 제조업체와 제품 번호(크기), 글꼴, 표시할 필드, 정렬 기준을 차례로 지정합니다. 사용자 지정 크기도 만들 수 있습니다.
  • 조건부 서식: 보고서 컨트롤에도 폼과 같은 방식으로 적용합니다. 예: 판매량이 목표보다 작으면 빨간색.
  • 날짜 정보: =Date()(오늘 날짜), =Now()(날짜와 시간), =Format(Date(),"yyyy년 mm월 dd일"). [날짜 및 시간] 명령으로 넣으면 보고서 머리글에 추가됩니다.
  • 페이지 레이아웃: [페이지 설정] 탭에서 용지 크기, 방향, 여백, 열을 지정합니다. 디자인 보기에서 보고서 너비가 용지 너비에서 여백을 뺀 값보다 크면 빈 페이지가 생깁니다.

오브젝트 프로그래밍 개념

중요도 ★★☆
개념뜻 / 예
개체 (Object)폼, 보고서, 컨트롤처럼 다룰 수 있는 대상
속성 (Property)개체의 특성. Me.txt이름.Visible = False (형식: 개체.속성 = 값)
